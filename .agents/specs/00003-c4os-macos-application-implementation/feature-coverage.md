# Normative Feature Coverage

State: Frozen and normative 2026-07-18

## Purpose

This file prevents the implementation summary from replacing or weakening accepted product behavior. Every row is required unless this spec explicitly records a deferral or feature/release gate. The accepted Context and linked Reference Files remain authoritative when a summary below omits detail.

## Planning And Closeout Rule

The post-Freeze sprint plan must map every coverage ID to one or more tasks. Each accepted task file must name the coverage IDs it implements and separate automated or source-based verification from human visual acceptance.

At implementation closeout:

- every coverage ID must be implemented and verified, or explicitly remain behind an accepted feature/release gate;
- every human-reviewable row must have a production-rendered artifact or state for user acceptance;
- no row may be treated as complete from wireframe behavior, source inspection, tests, logs, or inherited Proofs alone;
- Context remains authoritative if a task or implementation note conflicts with this file.

## Deferred-Feature Interpretation

The implementation contract defers actual detached Chat windows, full-screen/password-entry terminal behavior, browser sub-tabs, multiple simultaneous Reply targets, Windows/Linux production claims, Codex import, public-marketplace governance, native cross-runtime/environment migration, and unvalidated named SSH profiles.

These deferrals do not remove visible accepted affordances, safe unavailable states, or the requirement to avoid implying unsupported capability. The Browser pre-Freeze evidence gate passed; Browser implementation and production verification remain required before production availability can be declared, and its accepted UI states and controller boundary remain owned by ART-002.
